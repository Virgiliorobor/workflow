# tech-development

Workspace for building customs compliance tools, legal practice automation, and personal workflow utilities — from initial problem definition through a working, verified tool. Covers Python scrapers, React artifacts, full-stack SaaS, and document generation.

**Workspace type:** Developer
**Stages:** Define → Adjust & Aim → Build & Volume → Verify → Stage 5

---

## How to Use This Workspace

**If you use Claude Code or Cursor:**
Open this folder. On every new task, Claude will read `CLAUDE.md` first and understand the workspace. Tell it which stage you want to work in — it will navigate to the right `CONTEXT.md` and follow the stage contract.

**If you use Claude Projects:**
Upload the relevant files as knowledge sources. Start with `CLAUDE.md` and the stage `CONTEXT.md` for the task at hand. Add `_config/` files as needed.

**If you use any chat interface:**
Paste the contents of `CLAUDE.md` at the start of your session. Navigate to the stage you are working in and paste that stage's `CONTEXT.md`. Work from there.

## Workflow

1. **Define** — Identify the exact manual process being replaced: what is the input, the output, and the data source — answer all three before writing any code.. Output goes to `01_define/output/`.
2. **Adjust & Aim** — Choose the right form factor and stack for this specific tool — scraper vs. API client vs. artifact vs. full-stack — and sketch the architecture.. Output goes to `02_adjust-and-aim/output/`.
3. **Build & Volume** — Build the core function on one record first, verify manually, then add batch processing, delays, incremental saves, error logging, and progress indicators.. Output goes to `03_build-and-volume/output/`.
4. **Verify** — Run the complete tool against real data, check output format precisely, confirm edge cases (HTS notation, ruling number prefixes, document formatting), and document the result.. Output goes to `04_verify/output/`.
5. **Stage 5** — Generate a markdown file capturing development details: tool purpose, inputs/outputs, stack decisions, known issues, and final verified behavior.. Output goes to `05_document/output/`.

Human review happens at each `output/` directory before the next stage begins.
